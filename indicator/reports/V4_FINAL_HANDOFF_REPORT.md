# V4 final handoff report: HC-MTF signal engine, root-cause investigation

Written for an independent reviewer who has not seen the conversation or earlier summaries.
Every claim points to a repository file, test or measurement. All paths are relative to
`indicator/` in the `barry-capital` repository, branch `claude/mtf-conviction-indicator`.

## 1. Executive summary

**What was investigated.** HC-MTF is a TradingView Pine indicator with a Python research twin.
It prints ▲ BULLISH / ▼ BEARISH markers when a multi-timeframe swing-structure break occurs in
the direction of two higher-timeframe (HTF) trends. V3 found no market × timeframe × direction
cell that met its criteria for a demonstrated edge. V4 Phase 1 asked whether the engine is built
on a viable predictive hypothesis at all. It traced every stage of the code and re-measured the
raw events before any filtering, against four matched controls. It also audited v3's own
statistics.

**Three separate questions, three separate answers.**

| question | answer | basis |
|---|---|---|
| Is the software correct (no look-ahead, no repainting on closed candles, deterministic, bullish/bearish mirror-symmetric)? | **Yes, where tested.** 40/40 tests pass, including a new price-negation symmetry test. One defect: the Pine strategy twin resets its stop and time-exit clock when a same-direction signal arrives during an open trade (~3% of trades). Not fixed: production freeze | §3 F5, §6 |
| Does signal generation do what it says? | **It computes what the code specifies, but not what the indicator claims to be.** The only drawn signal (MAJOR) is the end of a pullback *inside* an existing HTF trend, never an HTF trend change. It arrives after a median 3.0–3.9 ATR of the move, and catches 7–47% of large swings | §3 F3 |
| Do the signals predict returns (trading performance)? | **No measurable predictive value after controls.** Under the pre-declared rule, 0 of 302 adequately sampled cells show information. Where signals beat unconditional random entries, matching on HTF state and year removes the effect. The result is underpowered for MAJOR outside 1H crypto (MDE 0.5–1.2 ATR) | §3 F1, F2; §4 |

**What remains unproven.**
* Whether the HTF trend state alone (time-series momentum, H6) or volatility compression → expansion (H7) carries information. Neither has been tested.
* Whether the single surviving cell (4H crypto bullish continuation) replicates.
* Whether the indicator behaves identically on TradingView's own data: no TV export has ever been compared.

**Recommendation: REPLACE HYPOTHESIS.** Stop developing the structure-break signal. Do not add
filters, components or repositories: there is nothing for them to select from. Test H6 and H7
(and replicate H1r) on data that is still untouched, under a plan committed before any number is
computed. See [`V4_HYPOTHESIS_REGISTER.md`](V4_HYPOTHESIS_REGISTER.md).

**Important limitation.** All V4 evidence uses data already examined in v1–v3; no untouched
holdout remains (§5). V4 can reject. It cannot confirm.

## 3. Findings supported by evidence

Definitions:

* **r_h**: direction-adjusted move to candle H, in ATR(14) at the signal, after round-trip
  costs. H is 1H 24, 4H 30, 1D 20, 1W 13 candles. Entry is the next open.
* **Controls**, per event, same symbol and side:
  * **R0**: every candle in the window;
  * **R1**: ±2H candles (pre-declared, biased, see F5);
  * **R1a**: the 2H candles after the event (post hoc);
  * **R2**: same calendar year and same HTF relation;
  * **R3**: same year and same ATR%-tercile.
* **Excess** = r_h − control, mean [95% calendar-month cluster bootstrap CI].
* **Adequate** = ≥ 100 events in ≥ 24 months.
* **Information** (pre-declared): CI lower bound > 0 against R1 and R2, median > 0 against R1,
  and still positive against R1 without the top 1% of events.

## 5. Validation and research integrity

* **Random-entry benchmark (v3, `metrics.random_baseline`).**
  * Matched: same symbol, whole window, count, side mix (permuted within symbol), horizon, costs.
  * Not matched: HTF state/regime, volatility, timing clusters.
  * The p-value treats draws as iid and omits the clustered error of the signal mean, so it is
    anti-conservative.
  * V4 replaces it with per-event controls R0/R2/R3 and a month-cluster bootstrap of the excess.
* **Dependence.**
  * Calendar-month clusters pool all symbols, which handles cross-asset co-movement within a
    month.
  * The same symbol's overlapping windows are only partly handled: 64–91% of raw breaks overlap
    the next break's window; MAJOR 2–10%.
  * 1W horizons span ~3 months, so a quarter-cluster variant is in the json.
* **Purging and embargo.**
  * `purgedcv.CombinatorialPurgedCV(6, 2, embargo 1%)` on time buckets with t1 = bucket end + H
    (`hcmtf/v3.py` `cpcv_selection`), as in PREREG_V3 amendment 1.
  * No rule is fitted, so it only protects the configuration-selection step.
* **Multiple testing.**
  * Holm over v3's C2 cells.
  * DSR with n_trials = 60, which is an underestimate: the full history is in the hundreds of
    comparisons (`V4_DATA_AND_VALIDATION_GAPS.md` V7).
  * V4 adds 364 cells and does not claim any positive result from them.
* **Pre-registered vs post hoc.**
  * Pre-registered: v3 plan `5c3fbfa` → amendment `873e572` → results `12a8803`; V4 plan
    `e62033f` → diagnostics `e9509b2`.
  * Post hoc and labelled: v3 event-weighted PBO/CPCV; V4 R1a/R1b split, `information_R1a`, H1r.
* **Final holdout.** **Not untouched.** v2 used FRESH symbols as its primary test. v3 ran all 70
  symbols on all dates, including the DEV holdout windows (`hcmtf/v3.py` `collect`). Untouched
  data is proposed in `V4_DATA_AND_VALIDATION_GAPS.md` §4: forward data after 2026-10-27 and 32
  named new symbols. None of these symbols is present in `data/` or referenced in code (checked).
* **Independent engines.**
  * backtrader (1,718 trades) and backtesting.py (5,279 trades) reproduce `evaluate.simulate`
    on hcmtf's own signals.
  * That establishes simulator consistency only: not signal correctness (same inputs), not
    the Pine twin (which differs, F5a), and not predictive validity.
* **Known limitations that could change the conclusion.**
  * Underpowered MAJOR cells (MDE 0.5–1.2 ATR outside 1H crypto).
  * A single primary horizon per TF.
  * Fixed costs.
  * ETF proxies for commodities.
  * Only ~35 months of non-crypto intraday.
  * A possible regime dependence: crypto 2020–2026 contains two large bull runs.
  * TradingView data and runtime never compared.
* **Configuration.** `engine.DEFAULTS` (pivots 5/3, 5/3, 5/2, 4/2; cooldown 12/6/5/4) with
  `reports/active_config.json` (no evidence, no filters, acceptance off); `evaluate.HORIZON`;
  `universe.COST_BPS`; bootstrap 1,000 reps (V4) / 2,000 (v3), seed 20261027.

## Questions for Independent Review

**Claims to challenge**
1. "Structure breaks carry no timing information." It rests on controls R0 and R2:
   * Is R2 (same calendar year and HTF state, using the whole year's candles) a fair control,
     or does matching on the calendar year leak information that understates the break's value?
   * Would a strictly causal control (only candles before the event, outside its run-up) change
     the result?
2. "The HTF gate's value is trend exposure, not the break." This is inferred from xR2 ≈ 0 inside
   the state; the state's own premium (H6) was not measured directly.
3. The single surviving cell (4H crypto bullish continuation, xR2 +0.66 [+0.07, +1.18] but median
   −0.33) is judged to be chance after 364 cells. Is dismissing it justified, or under-weighted?
4. V3's PROMISING labels are called unsupported because of iid p-values. Check
   `metrics.random_baseline`; check that the cluster CI of the excess is the right replacement.

**Assumptions that deserve scrutiny**
* ATR-normalised r_h pooled across very different assets.
* A single fixed horizon per timeframe.
* Fixed per-class costs.
* Month clusters as the independence unit; weekly horizons overlap them.
* Zigzag ≥ 4 ATR as the definition of a "real" swing for detection rates.
* "Adequate" = 100 events in 24 months, which is arbitrary but pre-declared.

**Most important missing evidence**
* Any untouched data. All V4 numbers are on previously examined symbols and dates.
* A TradingView export compared with the Python engine.
* Long non-crypto intraday history.

**Contradictions found**
* `V3_SUMMARY.md` attributes near-zero deflated Sharpe ratios to the 60-trial correction. For
  1H crypto bullish and 4H crypto bearish, the bucket Sharpe is itself negative while the
  per-event mean is positive.
* `V3_SUMMARY.md` calls three cells PROMISING on p = 0.005. Their cluster CIs of excess over
  random include 0 (4H bearish) or touch it (4H bullish).
* The backtesting.py agreement was presented as cross-validation of "the" strategy. It validates
  the Python simulator, which differs from the Pine twin (F5a).
* The V4 pre-declared local control R1 turned out to be biased (F5c). The pre-declared rule is
  stricter than intended; the post-hoc R1a variant changes 0 → 3 passing cells.

**Strongest evidence for the conclusion.** 0/302 adequately sampled cells under the pre-declared
rule. Consistent ≈ 0 or negative excess of raw breaks against R0 and R2 in the best-powered
cells (1H crypto MDE 0.22 ATR; 1H/1D rates & FX and 1D/1W equities 0.2–0.5). This agrees with
v2 (no component passed screening) and v3 (CPCV preferred "every break").

**Strongest evidence against it.**
* 1H crypto bullish MAJOR beats unconditional random (xR0 +0.38 [+0.14, +0.60]) and the
  after-window control (xR1a +0.24 [+0.09, +0.38]) on 4,348 signals.
* 4H crypto bullish continuation survives all three unbiased controls on the mean.

If the R2 control is too strict, the structure break in a bullish crypto trend may carry a small
edge.

**Single biggest unresolved methodological risk.** No untouched holdout remains. Every hypothesis
has been shaped by the same 70 symbols, so any surviving positive is suspect and any future
"confirmation" must come from new symbols or forward data declared before they are looked at.

**Single next experiment most likely to change the decision.** Test H6 (HTF trend state alone,
both sides separately) on the frozen new-symbol set plus forward data, against R0 with
cluster-bootstrap inference:
* If the state carries a robust premium that the break does not add to, the decision stands:
  replace the break with a state-based rule.
* If the state has no premium either, the HTF-direction idea is exhausted too.
* If the break adds to the state on new data (the H1r pattern replicating), the decision would
  move to RESEARCH FURTHER.
